# Bug 检查与 demo 视频

日期：2026-10-27。检查范围为当前占位版的客户端异步流程、控制权、窗口交互、规则边界与数据库故障。此次未变更用户原有房间进度；视频使用新建演示房间。

## 已修复

| 问题 | 触发方式与后果 | 修复与验证 |
| --- | --- | --- |
| 旧房间响应污染新房间 | 进入房间后立刻切换，旧 enter/sync 响应晚到，可能覆盖状态或提示 | 请求绑定连接与生命周期代次；前端测试验证旧响应不影响新房间 |
| 重连同步时提交卡住 | 初始同步尚未结束便提交答案，原同步锁忽略了这次重试 | 同步期间记录后续处理请求，完成后自动处理；测试验证无需点击“重新核对” |
| 草稿/待确认操作回退 | localStorage 写入或删除失败，读取时又拿到旧持久化值 | 失败写入使用内存覆盖，失败删除保留空值标记；故障测试通过 |
| 复制标签页自动抢控制权 | 浏览器复制 sessionStorage，连 tabId 和 controlEpoch 一起复制 | 只要原控制连接仍在线，新连接必须显式接管；集成测试覆盖完整复制与普通新标签 |
| 进入房间确认重试丢控制权 | 同一个 Socket 重试 enter，旧 epochHint 导致错误降为只读 | 同连接进入请求幂等，保留当前控制代次；集成测试覆盖 |
| 通关提示被题面遮住 | 自己或队友解出 final 时，另一人正在查看题目 | 私人题面中也展示不抢焦点的通关提示，原草稿保留；双浏览器实测与视频可见 |
| 错误类型关闭窗口 | 对谜题窗口发送 npc:close 但携带有效 viewId | 同时核对窗口类型；规则回归测试通过 |
| 数据库重启可能使游戏崩溃 | PostgreSQL 断开空闲连接，连接池发出未处理 error 事件 | 处理连接池事件并让 pg 自动更换连接；集成测试主动断开本次测试连接，随后健康检查和读取存档正常 |
| 已断开的连接被记为在线 | 数据库 enter 操作完成前连接已关闭 | 完成数据库调用后重新检查连接；离线时释放控制与移动节流记录 |
| 角色编号与外观不一致 | 先加入的玩家选择角色二，原先仍显示席位号 1 | 地图和侧栏按选定角色显示编号与颜色，席位身份仍独立 |

还修复了换房时通关横幅和恢复码面板状态未重置的问题，并保护提交回执不误删另一标签新产生的待确认命令。

## 验证结果

- `npm test`：25 项通过，包含新增的 5 项前端异步/存储测试与窗口类型测试。
- `npm run test:integration`：9 个子场景通过，外层套件计入 Node 统计时为 10；使用真实 PostgreSQL 和独立 HTTP/Socket.IO 会话。
- `npm run build`：TypeScript 与生产构建通过。
- 两个真实浏览器会话完成推人/墙、不同题面并存、共享开锁、改错受困、重新解救、NPC、共同跨图、final 双解、通关后改错、刷新恢复与继续移动。
- 此次没有公网主机及不同网络的双设备测试，也不把这些测试结果等同于所有浏览器/网络故障都已排除。

## Docker 结论

当前本地开发、真实联机测试、持久化数据库与 demo 制作都已通过原生 Node.js 24 + PostgreSQL 18 完成，Docker 不是必需条件，因此此次没有修改系统 Docker/WSL 配置。现有容器部署文件保留；选择使用它们正式部署时，仍需在目标主机上构建镜像并验收 TLS、代理和备份。
